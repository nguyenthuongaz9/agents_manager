# Operational Workflow: Dynamic Lifecycle

The system adapts its workflow based on the product type.

## Phase 1: Intake & Analysis
1.  **User submits request** (e.g., "Build a Cross-platform Mobile App").
2.  **Leader Agent analyzes** the product domain.

## Phase 2: Team Assembly (NEW)
1.  **Leader selects the Task Force:**
    *   Example for Mobile: Leader + Tech Lead + Mobile Dev + UX Designer + QA.
    *   Example for Tool: Leader + Tech Lead + Systems Programmer + Tech Writer + QA.
2.  **Leader sets the context:** Injects domain-specific rules (e.g., Apple Human Interface Guidelines for iOS).

## Phase 3: Planning & Tasking
1.  **Leader + Tech Lead** create the Architecture.
2.  **Leader assigns tasks** to the newly assembled specialized team.

## Phase 4: Execution & Domain Review
1.  **Specialists** work on implementation.
2.  **Tech Lead** reviews code based on the specific product domain standards.

## Phase 5: Domain-Specific QA
1.  **QA/QC** performs tests relevant to the product (e.g., "Does it run on Android 12?" or "Is the CLI output POSIX compliant?").

## Phase 6: Delivery
1.  **Leader Agent** packages the product.
2.  Final delivery to User.
